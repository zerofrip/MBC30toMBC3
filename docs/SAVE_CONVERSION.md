# MBC30 ⇄ MBC3 セーブデータ変換

## 対応範囲

未改造日本語版ポケットモンスター クリスタルのMBC30セーブと、このリポジトリのMBC3 Offlineパッチのセーブを変換します。コマンドの詳しい引数は `python3 tools/convert_save.py --help` で確認できます。

セーブのみから改造版の種類やROMハッシュを確定することはできません。識別値・チェックサムが通っても任意のROM改造に対応するわけではありません。海外版クリスタル、金銀、他のMBC3／MBC30ゲーム、異なる配置のMBC3化パッチ、RC5・251匹版などは本ツールの検証対象外です。

対応するファイルサイズは以下だけです。拡張子による判定はしません。

| 元の形式 | 入力サイズ | コマンド | 出力サイズ |
|---|---:|---|---:|
| 日本語原版MBC30 | 65,536バイト | `to-mbc3` | 32,768バイト |
| 本プロジェクトのMBC3版 | 32,768バイト | `to-mbc30` | 65,536バイト |

ヘッダ付きファイル、RTCを末尾に付加したファイル、パディングで容量を拡張したファイル、圧縮ファイル、エミュレータのステートは受け付けません。サイズが違うデータを自動的に切り詰めることもしません。

## 使い方

リポジトリ直下で、実際のセーブファイル名に置き換えて実行してください。

```sh
python3 tools/convert_save.py to-mbc3 original.sav --output offline.sav
python3 tools/convert_save.py to-mbc30 offline.sav --template original.sav --output restored.sav
```

エミュレータ・ゲームを終了し、レポートがセーブファイルへ書き出された後に変換してください。出力は対応するROM用のセーブとして設定します。利用先が要求する名前・拡張子はその環境に合わせてください。元のファイルは保管したままにしてください。

`--template` は、**同じ主人公の元の64KBセーブ**を指定します。現在の32KB側の進行状況が優先され、手持ちやボックスを古い状態に戻すことはありません。32KBに存在しない通信領域と移動先に使った未使用9バイトを復元元から補います。変換後に一度もプレイ・編集していなければ、64KB→32KB→64KBの結果は元の64KBと全バイト一致します。

元の64KBがない場合も逆変換できます。

```sh
python3 tools/convert_save.py to-mbc30 offline.sav --output restored-new.sav
```

この場合、上位32KBは0から初期化し、性別など7バイトだけを書き戻します。通信フラグ・モバイル設定・通信履歴・ランキングなどは0となります。ゲーム本体の新規開始時の定型文などは生成しません。**通常の冒険の再開を検証した方式であり、通信サービスへの再接続やモバイル画面の完全な初期化を保証しません。**

## 通信データとRTC

- 64KB→32KBでは上位32KBの通信領域を持ち込めません。元の入力がその領域の唯一の保管先になります。
- 復元元を指定した逆変換では通信領域を元の時点のまま保持します。MBC3版で遊んだ期間の通信統計などを再構築することはできません。
- モバイル交換の預かり状態が0でない入力・復元元は拒否します。預けたポケモンや古い取引状態を持ち越さないため、元の環境で解消してから変換してください。強制変換オプションはありません。
- 通信フラグ2バイトはMBC3へ変換する際には保存しますが、MBC3版のゲームはロード時に0にし、その後のレポートで0を保存します。
- SRAM内の時計関連データは通常データとともに保持します。ただし時計レジスタ、エミュレータ固有のRTC付加データ、別のRTCファイル、実機側の時刻は変換・同期しません。利用先でゲーム内時刻を確認してください。

## 検証とファイル保護

- 主セーブ・バックアップそれぞれの日本語版識別値と16ビット加算チェックサムを確認します。両方不正なら拒否します。
- 片方だけ有効なら、無効な側を勝手に修復せずそのまま変換し、警告を表示します。変換後にゲーム内で読み込み・保存してください。
- 両側が有効でも主人公ID・名前が異なる場合は拒否します。復元元との比較にも同じID・名前を使用します。この比較は同一セーブ系列であることの暗号学的証明ではありません。
- 性別の値は0または1に限定します。チェックサム対象外の全領域や個々のポケモンの整合性まで検査する機能ではありません。
- 入力・復元元は読み取り専用で扱います。出力先が既存ファイル、シンボリックリンク、入力のハードリンクの場合は拒否します。
- 正常終了コードは0、入力不正や出力不能は2です。変換結果のサイズとSHA-256を表示します。ツールはネットワーク通信を行いません。

## 保存位置

以下はセーブファイル先頭からのオフセットです。

| データ | MBC30 | MBC3 |
|---|---|---|
| 性別など7バイト | `0x8000..0x8006` | `0x7F20..0x7F26` |
| 通信フラグ2バイト | `0x860E..0x860F` | `0x7F27..0x7F28` |
| 通信領域 | `0x8000..0xFFFF`（上記移動データを含む） | 保存不可 |

下位32KBは移動先9バイト以外をそのまま保持します。逆変換では9バイトを復元元の値、または復元元がなければ0に戻します。主セーブのチェックサム対象は `0x2009..0x2AE2`、格納先は `0x2D0D..0x2D0E`。バックアップはそれぞれ `0x7209..0x7CE2`、`0x7F0D..0x7F0E` です。移動する9バイトはいずれの対象範囲にも入らないため、チェックサムの再計算・変更は不要です。

## 動作確認

ROM不要の合成セーブテストでは、男女の全バイト往復一致、プレイ後の進行状況の優先、復元元なしの初期化、片側のみ有効なセーブ、破損・サイズ不正・別主人公・預かり状態・出力先の保護を確認しました。

エミュレータでは男女×復元元あり／なしの4ケースで、未改造ROMからMBC3への読み込み、歩行による位置変更とレポート保存、未改造ROMへの逆変換・読み込み・保存、再度MBC3へ変換して再起動する流れを確認しました。性別・主人公情報・位置・手持ち・ボックスを確認しています。

実機での変換セーブの使用、モバイル画面や通信サービス、RTCの引き継ぎ、全ストーリーの通しプレイは未検証です。実行例は [VALIDATION.md](VALIDATION.md) を参照してください。
